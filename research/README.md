# PRISM DID Adoption Research

This folder captures the current state of research for bringing the `did:prism` method to ACA-Py and Credo-TS. The work is split into focused documents so each stakeholder can dive directly into the part that matters to them.

## Map of deliverables

- [`prism-did-adoption/01-did-methods.md`](./prism-did-adoption/01-did-methods.md) – DID method inventory and capability comparison versus `did:prism`.
- [`prism-did-adoption/02-component-analysis.md`](./prism-did-adoption/02-component-analysis.md) – Key ACA-Py, Credo-TS, SDK-TS, and NeoPRISM components that touch DID methods and how their responsibilities line up.
- [`prism-did-adoption/03-gap-analysis.md`](./prism-did-adoption/03-gap-analysis.md) – Capability gaps, existing blockchain dependencies, and library work required for PRISM alignment.
- [`prism-did-adoption/04-implementation-plan-acapy.md`](./prism-did-adoption/04-implementation-plan-acapy.md) – Proposed plan, phases, and checkpoints for ACA-Py.
- [`prism-did-adoption/05-implementation-plan-credo.md`](./prism-did-adoption/05-implementation-plan-credo.md) – Proposed plan, phases, and checkpoints for Credo-TS.
- [`prism-did-adoption/06-infrastructure-and-architecture.md`](./prism-did-adoption/06-infrastructure-and-architecture.md) – Infrastructure requirements plus current and future-state diagrams (flowcharts + sequence diagrams).
- [`prism-did-adoption/07-recommendations-risks.md`](./prism-did-adoption/07-recommendations-risks.md) – Implementation recommendations, phased rollout narrative, and risk register.
- [`prism-did-adoption/08-decisions-testing-docs.md`](./prism-did-adoption/08-decisions-testing-docs.md) – Outstanding decisions/tradeoffs, documentation backlog, and the proposed unit/integration/e2e test matrix.
- [`prism-did-adoption/09-vdr-requirements.md`](./prism-did-adoption/09-vdr-requirements.md) – VDR requirements for ACA-Py and Credo-TS aligned with the PRISM VDR specification and resulting action items.

Each document references the exact files/lines within this repository (or included submodules) that informed the findings so you can trace every recommendation back to source material.
